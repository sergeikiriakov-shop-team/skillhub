# SkillHub — демо «с нуля» своим аккаунтом

Короткий сценарий, чтобы показать команде полный путь работы со SkillHub на чистом окружении:
подключение MCP → вход своим GitHub → загрузка → оценка → поиск/установка.

- **Портал:** https://166.1.29.218.sslip.io
- **MCP:** `https://166.1.29.218.sslip.io/mcp`

---

## 0. Перед демо — привести окружение к чистому состоянию

Чтобы пройти путь «как новый участник команды», убираем у себя MCP и скиллы SkillHub:

```bash
# снять MCP (user scope)
claude mcp remove skillhub -s user

# убрать установленные скиллы SkillHub (исходники остаются в репозитории)
rm -rf ~/.claude/skills/skillhub ~/.claude/skills/connect-skillhub
```

Проверка: `claude mcp list` не показывает `skillhub`, в `~/.claude/skills/` нет папок `skillhub`/`connect-skillhub`. **Перезапустите Claude Code.**

> Реестр на сервере при этом не трогаем (там боевые скиллы команды). Если для демо нужно
> убрать из каталога **свои** скиллы — см. раздел 6.

---

## 1. Подключить MCP одной командой

```bash
claude mcp add --transport http --scope user skillhub https://166.1.29.218.sslip.io/mcp
```

- `--transport http` — удалённый MCP по URL (ни Docker, ни образа, ни токена).
- **Перезапустите Claude Code** и проверьте: `claude mcp list` → появится `skillhub`
  (может писать «Needs authentication» до первого входа — это нормально).

## 2. Вход своим GitHub (один раз, в браузере)

При **первом** вызове любого инструмента SkillHub Claude Code сам откроет браузер для входа
через **GitHub (OAuth)**. Подтвердите — токеном управляет Claude Code, копировать ничего не нужно.

Доступ по роли: свежий аккаунт — `viewer`/`contributor`; оценивание (`evaluator`) и управление
пользователями (`admin`) выдаёт админ. Войти может только тот, у кого есть доступ к настроенному
GitHub-репозиторию.

## 3. Проверить, что всё живо

Просто спросите Claude Code обычным текстом:

> покажи статистику SkillHub

или

> что есть в SkillHub про SQL?

Это дёрнет первый инструмент и запустит вход из шага 2.

## 4. Загрузить скилл

> импортируй этот SKILL.md в SkillHub

- Реестр хранит **одну запись на имя**: повторная загрузка того же имени создаёт новую **версию**,
  а не копию. Авторство берётся из вашего GitHub-аккаунта (подделать нельзя).
- Контент, **идентичный** существующему скиллу под другим именем, отклоняется (409); просто
  **похожий** — принимается с предупреждением.

## 5. Оценить скиллы (роль evaluator)

> оцени неоценённые скиллы в SkillHub

Claude Code возьмёт очередь (`GET /api/skills?evaluated=false`), загрузит единую рубрику
(`GET /api/rubric`), проставит оценки **у себя** по одному алгоритму и отправит результат обратно
(`POST /api/skills/{id}/assessment`). Ключевая идея: **сервер не вызывает LLM — считает ваш Claude Code**.

## 6. Найти и установить скилл себе

> установи скилл `<имя>` из SkillHub в мой проект

Claude Code запишет `SKILL.md` (и `references/`) в `.claude/skills/<имя>/`.

## (Опционально) Убрать из каталога только свои скиллы

Если для чистого демо нужно удалить из реестра **свои** скиллы (чужие не трогаем). Делается на
сервере (у MCP нет инструмента удаления). **Сначала бэкап:**

```bash
ssh skillhub 'cd /opt/skillhub && docker compose -f docker-compose.prod.yml exec -T db \
  sh -c "pg_dump -U \$POSTGRES_USER -d \$POSTGRES_DB" </dev/null > backup-$(date +%F-%H%M%S).sql'
```

Затем удалить свои скиллы (каскад уберёт версии/оценки/эмбеддинги). Пример — по автору:

```sql
DELETE FROM skills
WHERE created_by_user_id = (SELECT id FROM users WHERE email = 'вы@example.com')
   OR author LIKE '%вы@example.com%'
RETURNING id, name;
```

> Восстановление из бэкапа: `psql -U $POSTGRES_USER -d $POSTGRES_DB < backup-….sql` внутри
> контейнера `db`.

## Что говорить команде по ходу (акценты)

- **Сервер ничего не «думает».** Оценка/категоризация/синтез идут на **собственном аккаунте**
  каждого разработчика; сервер только хранит скиллы и единую стратегию.
- **Единый алгоритм для всех** — рубрика лежит на сервере (`/api/rubric`), поэтому оценки сопоставимы.
- **Подтверждённое авторство** — личность из GitHub, подделать нельзя.

Подробности и диаграмма — в `docs/skillhub-presentation.html`.
